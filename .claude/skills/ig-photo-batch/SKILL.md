# IG Photo Batch

## 使用情境

使用者把料理照片放進 `input/`，要求裁切成統一比例並套上跟其他貼文一致的濾鏡風格，準備發 IG。每張照片的裁切範圍都要經過使用者確認，不能自動定案。

## 步驟

> 自動預覽：`scripts/auto_preview.py` 會透過 hook 每週一次（滿 7 天後第一次開對話/送訊息時）自動幫新照片跑完步驟 1～2b，預覽圖與參數（同名 `.json`）已經在 `.cache/previews/`。看到 `[auto_preview]` 提示時，直接從步驟 2c（顯示給使用者、檢查比例）開始，不用重跑 auto-detect。

1. **找出新照片**：
   ```
   .venv\Scripts\python.exe scripts\process_photo.py list-new
   ```
   會印出 `input/` 裡還沒出現在 `output/` 的照片清單。一次抓一批（建議 5 張左右）處理，不要一次把所有新照片都產生預覽——會混在一起分不清楚哪些是目前要看的。

   開始產生這一批的預覽之前，先清掉上一批留下的檔案：`.cache/previews/` 清空（例如刪掉裡面所有檔案），確保資料夾裡只有「這一批」的預覽圖，使用者才不會搞混進度。

2. **對每一張新照片，先自動偵測主體，再給使用者看一次確認**：
   a. 先跑自動偵測，拿到建議的 `offset-x`/`offset-y`/`zoom`/`rotate`：
      ```
      .venv\Scripts\python.exe scripts\process_photo.py auto-detect "<照片路徑>"
      ```
      會印出 JSON，例如 `{"detected": true, "rotate": 90, "offset_x": 0.05, "offset_y": -0.08, "zoom": 1.0}`。這是用電腦視覺（偵測圓盤/碗的邊緣，偵測不到圓形時改用飽和度+邊緣對比）算出來的建議值，不是瞎猜，實測對大部分圓盤/碗構圖的照片效果已經不錯，**明顯減少需要手動試 offset/zoom/rotate 的次數**。
      - 如果 `"detected": false`（偵測不到明顯主體，例如畫面太滿版、對比太低），直接退回用預設參數（不加任何 offset/zoom/rotate）產生預覽，跟以前一樣走手動調整流程。
   b. 用偵測到的參數產生預覽：
      ```
      .venv\Scripts\python.exe scripts\process_photo.py preview "<照片路徑>" --offset-x <值> --offset-y <值> --zoom <值> --rotate <值>
      ```
   c. 用 Read 工具把 `.cache/previews/<檔名>.jpg` 顯示給使用者看，**同時實際檢查輸出檔的寬高比**（例如用 `Image.open(...).size` 算一下，確認是 4:3 / 1.333），不要只憑肉眼猜，之前發生過誤判的狀況。
   d. 問使用者這個畫面（連同濾鏡後的樣子）可以嗎。大部分情況下自動偵測的結果應該就能直接用；如果還是需要調整：
      - 覺得主體太小、想裁緊一點、放大主體：在自動偵測給的 `--zoom` 基礎上再加大（數字越大主體越大，裁掉的周邊也越多）。
      - 想把畫面裡的主體往某個方向移：調整 `--offset-x`/`--offset-y`，數值是相對圖片寬高的比例。**注意方向是反的**——這兩個參數移動的是「裁切框」，所以要讓畫面主體看起來往右/往下移，`--offset-x`/`--offset-y` 要給負值（比自動偵測的值更小）；要讓主體往左/往上移，給正值（比自動偵測的值更大）。調整後一定要重新產生預覽實際看過，不要只憑公式判斷對不對。
      - 自動偵測判斷的 `--rotate` 覺得不對：可以手動改成 `0` 或 `90`/`180`/`270` 試試其他角度。
   e. 帶著新參數重新執行 `preview`、重新顯示，直到使用者滿意。

3. **確認後輸出最終檔**：**自己看照片內容直接判斷菜名**，不用每次都問使用者——使用者明確說過希望這步自己判斷就好。用 `--name` 給出：
   ```
   .venv\Scripts\python.exe scripts\process_photo.py finalize "<照片路徑>" --name "<菜名>" [同樣的 --offset-x/--offset-y/--zoom/--rotate 參數]
   ```
   會存到 `output/<菜名>.jpg`，並自動把 `input 檔名 -> 菜名` 記錄進 `output/manifest.json`（`list-new` 靠這個判斷進度，不是比對檔名）。**不要省略 `--name`**，否則會退回用 input 的原始亂碼檔名存檔。
   - finalize 前先用 `ls output/*.jpg` 之類的方式看一下現有菜名有沒有撞名（包含看起來像同一道菜的不同張照片）。真的撞名時不要直接覆蓋掉前一張，取個可區分的名稱（例如「紅燒排骨2」），讓兩張都保留。
   - 真的看不出是什麼菜（例如食材/做法太模糊判斷不出來）才需要開口問使用者，不要每張都問。

4. **全部處理完後**：把新成品推上 GitHub，進入自動發文佇列（見 CLAUDE.md「自動發 IG」）：
   ```
   git add output/ && git commit -m "Add <菜名們>" && git push
   ```
   接著跑 `.venv\Scripts\python.exe scripts\publish_ig.py next` 看下一篇是哪張、什麼時候發。跟使用者回報這次處理了幾張、佇列裡還有幾張。

## 單張例外參數

這些都是「只影響這一張」的覆寫，不碰 `process_photo.py` 開頭的全域濾鏡常數：
- `--warmth F`：暖色調強度倍率，預設 1.0。
- `--sharpen F`：銳化強度倍率，預設 1.0；近距離特寫容易銳化過頭，可以調低甚至設 0。
- `--brightness F`：亮度倍率，預設 1.0；過曝太亮可以調低（例如 0.85）。
- 只有使用者明確說「以後全部照片都要改」時，才去改 `process_photo.py` 裡的全域常數；單一張的需求一律用上面這些參數處理。

## 注意事項

- `preview` 和 `finalize` 用的是同一套裁切/濾鏡邏輯（`process_photo.py` 的 `process()` 函式），使用者看到的預覽跟最終輸出一定一致，不會有落差。
- 濾鏡參數是固定寫在 `apply_style()` 裡的全域設定，目的是讓所有照片風格一致——不要因為某張照片覺得不夠好看就臨時改全域濾鏡參數，單張需求請用上面的 `--warmth`/`--sharpen`/`--brightness`。
- 已經記錄在 `output/manifest.json` 裡的 input，`list-new` 不會再列出來；使用者如果要重做某一張，直接針對該張重跑 `preview`/`finalize`（記得帶上同樣或新的 `--name`）即可——如果菜名有變，`finalize` 會自動清掉舊菜名的輸出檔，不會留下重複檔案。
- 如果照片是 HEIC 格式且 Pillow 打不開，先確認 `.venv` 有沒有裝 `pillow-heif`（`scripts/requirements.txt` 裡是否已列出），沒有的話先補裝。
- `auto-detect` 不是百分之百準：對「整個畫面已經被食物塞滿、看不太到盤子邊緣」的照片效果較差（偵測不到清楚的圓形邊界時容易誤判、算出過度裁緊的結果），這種照片自動偵測結果出來後务必先看過預覽再決定要不要用，不要自動就 finalize。另外**不要拿已經處理過的 `output/` 成品圖再跑一次 auto-detect**——它是為了偵測「原始生圖」設計的，拿已經裁好的圖再偵測一次會因為已經沒有多餘的留白可裁，算出離譜的過度放大結果。
